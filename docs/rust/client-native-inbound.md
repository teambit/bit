# Native client fetch and import

With `BIT_RUST_CLIENT_VCS=on`, the Node `bit` entrypoint offers ordinary inbound commands to the Rust workspace worker before loading Harmony. Rust resolves file and HTTP remotes, validates incoming model and object bytes, and retains them until publication. JavaScript receives only scalar IDs, statuses, and progress; it uses the public `FetchCmd` or `ImportCmd` to format the final report. If Rust declines before publication, the existing command runs. Once `commandInboundApply` begins, errors propagate instead of replaying the command.

The supported command surface is:

| Command                                                 | Native handling                                                                                                                              |
| ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `bit fetch [ids...] --components` (`-c`)                | Fetch component objects, with optional `--all-history`                                                                                       |
| `bit fetch <scope>/<lane> --lanes` (`-l`)               | Fetch one explicit lane's component closure and remote refs from a configured file or HTTP scope, without publishing the Lane object locally |
| `bit import [ids...] --objects` (`-o`)                  | Fetch objects without writing component files, with optional `--all-history`                                                                 |
| `bit import`                                            | Refresh objects for components in the workspace bitmap                                                                                       |
| `bit import <id> --skip-dependency-installation` (`-x`) | Fetch objects and write ordinary component files and bitmap entries when Rust's preflight accepts the workspace policy                       |

Implicit, multi-lane, and `--all-history` lane fetches, `fetch --from-original-scopes`, JSON output, merge/override, and explicit import that requires dependency installation retain the public JavaScript path. Rust also declines unsupported remote or workspace policies before writing anything.

The source adapter test is `node --test scripts/rust-object-import/workspace-inbound-driver.test.cjs` with `BIT_LEGACY_ROOT` set to a prepared CLI. The public differential fixture is `node scripts/rust-object-import/cold-inbound-qualification.cjs <prepared-cli> <native-helper> <report.json>`. It creates disposable exported scopes, serves them through both `file://` and a loopback HTTP route, and checks exact public report output, logical object bytes, parsed index records, bitmap, workspace files and modes, the entire `.bit` path inventory and stable metadata file hashes, source-scope immutability, native request ownership, and zero Node object-body bytes against Node, native, missing-helper, and crashed-helper modes. It explicitly rejects synthetic HTTP remote paths under `.bit`. Canonical Node recompresses some verified remote objects, so the fixture retains both compressed SHA-256 maps in each raw artifact while comparing object hashes and inflated bodies for semantic parity. Canonical index record order can vary with HTTP completion order, so qualification compares index entries by ID and object hash while retaining raw index bytes in each artifact. Public report order remains an exact comparison. The fixture supports `extraFiles` through its exported `run()` API for wider payloads.
