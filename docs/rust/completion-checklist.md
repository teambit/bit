# Dependency scanning and parsing completion

Issue [#4](https://github.com/zkochan/bit/issues/4) covers the dependency extraction backend. All implementation work packages have reviewable changes and evidence. PRs [#28](https://github.com/zkochan/bit/pull/28), [#29](https://github.com/zkochan/bit/pull/29), [#30](https://github.com/zkochan/bit/pull/30), [#31](https://github.com/zkochan/bit/pull/31) and [#32](https://github.com/zkochan/bit/pull/32) target `rust`; they require user review/merge. Default enablement remains a separate rollout decision. Warm component-loading, Rust package resolution, custom detector migration and object-store projects remain outside this issue.

The [final consolidated validation report](final-consolidated-validation.md) includes exact combined revisions, raw test logs, all existing pending case names and the fresh attested helper checks.

## Measured acceptance

- Startup-inclusive eligible extraction is **3.84×** faster than the batching-only control, including reads, transfer and real fallback work; target is 2×.
- Large cold actual status improves **22.40%** and graph **18.93%**, exceeding the 15% command target and observed variation.
- Large warm/startup median regressions are at most **0.71%**, below 5%. Small Node 22/24 and genuine install workloads show no material gain and pass their regression gates.
- Cold status sampled process-tree RSS falls **48.48%**; cold graph increases **0.70%**. Small/warm/install/sixteen-edit sampled-memory medians remain below the 10% increase gate. Helpers are included; no independent-peak sum is substituted for simultaneous memory.
- All accepted actual CLI reports compare complete unnormalized JSON. Sampler failures and PID races are zero; rejected preliminary probes are excluded and described separately.

See [final command acceptance](final-command-acceptance.md) for ranges, total process CPU, memory limitations, reproducible commands and exact frozen-runtime provenance. Performance is one-host workload evidence. Keep the backend opt-in and retain the `off` rollback selector while these PRs are reviewed and broader default rollout is considered.
