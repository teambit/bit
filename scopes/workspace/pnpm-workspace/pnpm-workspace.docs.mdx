## Overview

A pnpm workspace keeps its projects' dependencies and scripts in their own `package.json` files, and
pnpm installs it. This aspect lets Bit version such a workspace without changing how it is installed
or built: each project becomes a component that carries its `package.json` as source, and the
workspace root becomes the workspace-root component (see `teambit.workspace/workspace-root`).

## Adopting the workspace

```sh
bit pnpm init
```

runs at the root of the pnpm workspace. It creates a standalone Bit workspace, with its scope in
`.bit`, and runs the first sync. It writes `workspace.jsonc` and `.bitmap` only: `package.json` is left
alone, and no AI agent files are added, since every file at the root belongs to the workspace-root
component.

## Synchronizing the workspace

```sh
bit pnpm sync
```

tracks every project that the `packages` patterns of `pnpm-workspace.yaml` match, and the root, and
adds the `teambit.workspace/pnpm-workspace` entry to `workspace.jsonc`, which tells Bit that pnpm
installs this workspace. `bit status` lists what a sync would change: projects that are not tracked,
or that left or moved, and `workspace:` references to move to the catalog.
Run it again whenever projects are added, moved or deleted:

- a tracked project keeps its component id, even after its package is renamed.
- a project that left the workspace is untracked, or marked removed once snapped.
- a snapped project moved to another directory is moved along with `bit move <old-dir> <new-dir>`.
- the projects refer to their siblings by `catalog:`, and the catalog binds them to `workspace:*`,
  so a component imported into another workspace resolves them there too.

Bit does not install a synced workspace, pnpm does. Run `pnpm install` after the sync and after an
import, and `pnpm add <pkg> --filter <project>` to add a dependency. `bit install` points there, and
the commands that install as a step of their own (merge, a lane switch) leave it to pnpm too.

## The environment

The projects with a `build`, `test` or `lint` script get the `teambit.workspace/pnpm-workspace` env.
Its tasks write the workspace next to the capsules the way it was snapped, install it with pnpm,
run the script across it with `pnpm -r`, and save each package's output as its artifacts. The
projects with none of those scripts get the empty env.

`bit pnpm sync --env <env-id>` gives those projects another env. The env is saved in `workspace.jsonc`,
so a later `bit pnpm sync` without `--env` keeps it.
