# 1. Goal & result so far

[← back to bundle-plan index](../bundle-plan.md)

Ship the Bit CLI as a **single bundled JavaScript file** plus a thin ring of packages that genuinely cannot be inlined, instead of a 1.2 GB `node_modules` tree.

|                     | released bit (bvm 2.0.72) | bundled bit (this branch)                                                                                                           |
| ------------------- | ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| install size        | **1.2 GB**                | **182 MB** (59 MB bundle + 68 MB externals + ~42 MB shims — the SSR-bundle regression below is now fixed; see the breakdown below). |
| files on disk       | **141,008**               | **~5,670**                                                                                                                          |
| `bit --help` (warm) | 0.662 s                   | 0.642 s (SEA: 1.324 s — §9)                                                                                                         |
| `bit list` (warm)   | 0.914 s                   | **0.848 s** (SEA: 1.574 s)                                                                                                          |
| single executable   | —                         | **179 MB** `bit-app` (+ the `bundle/` support dir)                                                                                  |
| build time          | n/a                       | \~11 s esbuild + \~5 s codegen (+ \~40 s for the SEA variant)                                                                       |

Every command on the target list — and a good deal more — runs from `/tmp/bit-bundle` against workspaces in `/tmp/bundle-tests/*`, with **zero** reads from this repo or from `~/.bvm` (§7.3).

The two new rows (browser barrels + vendored harmony deps) are what actually closes
[known gap 1](14-known-gaps.md) for real: a third-party UI root's non-core aspects that bare-import a
covered core aspect (rather than importing its exact `.ui.runtime.js` file) now get real, compilable
code instead of `require(bit.app.js)[...]`, which cannot compile for any browser target at all.
Verified end-to-end against `community-cloud`/`bit-cloud`: `CLIENT_ONLY=true bit run community-cloud`
goes from the pre-existing 64-error baseline to **0 rspack errors**, confirmed executing for real in
a browser (React Router, Harmony's client bootstrap) — see [18-findings-log.md](18-findings-log.md)'s
2026-09-07 entry for the full verification.
